GlassMarble documentation.

The living architecture map for your codebase. GlassMarble reads your repository as it is — every language, every dependency — and keeps diagrams, governance, and AI answers in sync with the code. No server. No drift.

Go 1.25 MIT Static binary No backend Cosign · SBOM · SLSA

Introduction #

Most architecture docs are born in Figma and die on the next merge. GlassMarble inverts that: your repository is the source of truth. Every commit is parsed, merged into a deterministic graph, and projected into the artifacts you actually use — diagrams, reviews, and answers.

Use it as a compiler (source → graph), a database (portable GraphJSON), a visualizer (31 notations), and an agent (grounded AI that reads the graph, not guesses). One binary, gmb, covers all four. Install once; run in CI and locally with the same commands.

Hidden coupling — data → apiLayering & cyclesdrift with forbidden_deps + cycle_budget

Incremental by design. With an existing akg.json, GlassMarble diffs git diff HEAD and re-parses only changed files. The first run is a full scan; daily runs are seconds.

How it works #

Four phases turn source into truth, then three consumers keep that truth useful.

pipeline
source (17 langs) → ingest · tree-sitter → GAST · unified model
→ aggregate · packages & visibility → link · CPG + CFG/DFG + traits
→ AKG · akg.json (GraphJSON v3) → { visualize · 31 types | AI · 32 tools | govern · drift/compare/hotspot }
  • Ingest — file walk + tree-sitter walk in parallel workers; git-aware diff skips unchanged files.
  • Normalize — language tokens → GAST (same nodes for Go, TS, Python, …).
  • Aggregate — clustering into packages, FQNs, export visibility.
  • Link — call, interface, CFG/DFG, concurrency, and primitive traits → committed CPG.

After commit, --intelligence (default on) runs patterns → smells → events → snapshots → memory. See Architecture → Pipeline and Storage for limits.

When to use #

✅ Great for

Onboarding new teammates, PR / architecture reviews, living docs in CI (commit marbles/), and answering "where is X used?" without grepping for days.

🚫 Not for

Runtime profiling, dynamic tracing, or style linting. Static analysis only — heuristic edges carry confidence < 1.0.

Verify a release #

Installers verify SHA256 via checksums.txt automatically. For supply-chain hardening, verify Sigstore + SLSA + SBOM (attached per release).

bash

VERSION=latest; ARCH=linux_amd64
curl -fsSLO "https://github.com/Syamchand123/GlassMarble/releases/download/${VERSION}/gmb_${VERSION#v}_${ARCH}.tar.gz"
curl -fsSLO "https://github.com/Syamchand123/GlassMarble/releases/download/${VERSION}/checksums.txt"{,.pem,.sig}
sha256sum -c --ignore-missing checksums.txt
cosign verify-blob \
  --certificate-identity-regexp "https://github.com/Syamchand123/GlassMarble/.github/workflows/release.yml@refs/tags/${VERSION}" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --signature checksums.txt.sig --certificate checksums.txt.pem checksums.txt

SBOM via Syft / SPDX is attached to the release alongside SLSA provenance (intoto). Docker images are ghcr.io/syamchand123/glassmarble:{latest,latest,sha-xxxx} — distroless, linux/amd64+arm64.

Architecture — concepts #

GlassMarble is a four-layer compiler. Each layer has one job, one input, one output — easy to reason about, easy to test.

1 — Ingest

Walk the repo, parse with tree-sitter, emit RichTokens. Parallel workers; git diff skips unchanged files.

2 — Normalize

Tokens → GAST: one vocabulary for all 17 languages. Imports resolved, receivers mapped.

3 — Aggregate

Files → packages, FQNs, visibility. Builds the global definition index.

4 — Link

Call, interface, CFG/DFG, concurrency, primitives → committed CPG → atomic GraphJSON.

Code Property Graph #

The CPG is the union of four views of your code, computed statically:

  • AST — declarations, types, params, fields, and expressions as written.
  • CFG — branches, loops, switches, and exits as they execute.
  • DFG — assignments and data propagation.
  • Call Graph — static calls, polymorphic bindings, and concurrency edges.

Architecture Knowledge Graph #

The CPG is persisted as a deterministic, sorted GraphJSON (schema_version: 3) at .glassmarble/akg.json. One file, one truth — diffable in git, readable in any editor, queryable offline. No WAL, no separate RDF store.

json
{"schema_version":3,"commit_hash":"f438841…","version":5,"entrypoints":["cmd.analyze.init"],
"nodes":[{"id":"auth/login.go::Authenticator::Authenticate","kind":"FUNCTION","primitive":"NETWORK_IO",
"file_spec":{"path":"auth/login.go","line_start":18}}],
"edges":[{"source_id":"…","target_id":"…","type":"CALLS","line_number":22,"confidence":1.0}]}

GAST — one model, 17 languages #

Every language's tree-sitter CST is coerced into a GASTNode with the same fields — declarations, calls, scopes, and types. That lets the linker reason once, not 17 times, and keeps results comparable across a polyglot repo.

Pipeline in detail #

  • Name binding — case-insensitive receivers, selector-path deconstruction, duck-typed interfaces, and package-path stripping keep FQNs stable across renames.
  • Linker taxonomy — edges are typed (CALLS, IMPLEMENTS, EXTENDS, DEPENDS_ON, …) and grouped into structural / behavioral / dynamic / security families. See Relationship types.
  • Virtual subgraph — ViewSpec derives scope + link-level, collapses namespaces into virtual nodes, and optionally walks an entry-point. See Scope & link level.

Limitations #

  • 14 full grammars with tree-sitter; Kotlin / Swift / Scala are declaration-only (no intra-method CFG/DFG). JSON is treated as config.
  • Static analysis only — no runtime inspection; heuristic edges carry confidence < 1.0.
  • Store is GraphJSON v3 — Turtle/RDF export is planned for future releases.
  • aging, fusion, learning are pipeline phases invoked via gmb analyze, not standalone commands.

TUI vs plain / JSON #

GlassMarble shows a Bubble Tea TUI when both stdin and stdout are terminals. Pipe it, run in CI, or pass --json and you get plain text / JSON — never interactive, always stable for scripts and tests.

gmb analyze — the workhorse #

Runs the four phases and atomically commits the graph. With --intelligence (on by default) it also writes intelligence, snapshots, and memory — all non-fatal and idempotent.

usage
gmb analyze [--full] [--commit <hash>] [--workers <n>] [--link-level architecture|standard|full] [--include-docs] [--bench] [--json]
  • Default is incremental: git diff HEAD → only changed files are re-parsed.
  • --full forces a full scan at full detail (slower, includes per-branch CFG/DFG).
  • --bench asserts budgets — analyze ≤120s, commit ≤80s, state ≤50MB — and fails the run if they're exceeded.
  • Output is stable: Analyzed 3 files | 120 nodes | 240 edges | … | state=180KB | 0.4s

usage

Zero External CDNs 100% Local & Air-Gapped Embedded Cytoscape.js Embedded Mermaid 10.9 REST API

AKG — GraphJSON shape #

The entire architecture lives in one file — .glassmarble/akg.json — pretty-printed, sorted, and verified. Edit it by hand and gmb doctor will tell you if you broke it.

json
{"schema_version":3,"commit_hash":"f438841…","version":5,
"entrypoints":["cmd.analyze.init","main.main"],
"nodes":[…],"edges":[…],
"summary":{"primary_patterns":["…"]},
"errors":[],"verified":true}
  • schema_version — always 3 for v1.0.
  • commit_hash / version — which commit was analysed and the monotonic graph revision.
  • nodes / edges — sorted arrays; diff them in git to see structural change.
  • verified — true after post-write verification; errors holds any dropped edges.

Nodes #

json
{"id":"auth/login.go::Authenticator::Authenticate","kind":"FUNCTION","name":"Authenticate",
"primitive":"NETWORK_IO","file_spec":{"path":"auth/login.go","line_start":18,"line_end":45},
"properties":{"fully_qualified_name":"auth.Authenticator.Authenticate","return_type":"string"}}

IDs are <path>::<type>::<member> with ::param: / ::field: suffixes. Kinds include FUNCTION, STRUCT, INTERFACE, MODULE, PARAM, FIELD, ALIAS — v3 folds TYPE_DECL → STRUCT.

drift — architecture invariants #

Declare the layers you intend, then let gmb drift fail the PR when reality diverges. No drift: block means "check cycles only".

yaml
drift:
  layers:
    - name: api
      paths: ["cmd/**", "internal/app/**"]
    - name: internal
      paths: ["internal/**"]
  forbidden_deps:
    - source: internal
      target: api
  cycle_budget: 0  # 0 = any cycle fails

intelligence — thresholds #

All optional, zero falls back to defaults. Tune only when you have a reason — defaults catch real smells without noise.

  • god_object_fan_in_threshold:15 · small_cycle_threshold:3 · layered_consistency_threshold:0.80
  • snapshot_max_count:30 · snapshot_auto_threshold_nodes:15000 / mb:8

Agent loop #

The model never writes diagrams directly — it calls tools that read the AKG and then answers from the results.

flow
You: "which services depend on payments?"
AI → LLM: system prompt + repo header (nodes, edges, patterns)
LLM → AI: tool_call akg_traverse
AI → AKG: JSON facts
AI → LLM: tool results
LLM → AI: grounded answer + citations → You

32 tools — system 3, akg 21, code 5, diagram 3. Every tool call is traced to stderr (→ akg_status({}) / ← ok). File contents are always data, never instructions.

Streaming #

On by default. Tokens stream as they arrive; if the provider ignores stream:true, GlassMarble falls back to a single response. Disable per-run with --no-stream or globally with GLASSMARBLE_AI_STREAM=0.

gmb ai chat               # resume latest
gmb ai chat --new         # fresh session

Guardrails #

Give every run a budget so CI can't burn tokens:

bash
gmb ai --max-total-tokens 20000 "question"
gmb ai --max-cost 0.5 "question"

Checks run before the next request (pre-flight prompt-size) and after each completion. Stop reasons are surfaced as Note: token_budget / cost_budget / turn_limit; --verbose adds per-run accounting.

MCP Server — Model Context Protocol #

A native implementation of Anthropic's Model Context Protocol (MCP) that connects GlassMarble's living Architecture Knowledge Graph directly into modern AI developer tools. Launch it via gmb mcp.

MCP Spec 2024-11-05 30+ Compiler Tools 6 gmb:// Resources Stdio & HTTP/SSE Read-Only Enforced

Instead of feeding thousands of raw source files into an LLM context window or letting AI agents hallucinate call hierarchies, the MCP server gives assistants precise, compiler-verified tools to query types, calculate live blast radiuses, detect circular dependencies, and verify architectural invariants in milliseconds.

bash 
# Run MCP server on standard input/output (used by desktop and IDE clients)
gmb mcp

# Run MCP server over streamable HTTP with bearer token authentication
gmb mcp --transport http --port 8765 --auth-token "secret-token-here"

# Print ready-to-use client configurations
gmb mcp --print-config cursor
gmb mcp --print-config claude-desktop
gmb mcp --print-config windsurf
gmb mcp --print-config claude-code

Security & Sandboxing #

Because AI agents execute tools semi-autonomously, GlassMarble enforces rigorous defense-in-depth security boundaries:

Enforced Read-Only Mode

Runs in --read-only mode by default. All mutations, snapshot writes, or config modifications via MCP tools are blocked unless explicitly opted-in.

Roots-Aware Path Sandboxing

Every file path passed to tools is canonicalized and validated against client-declared workspace roots. Directory traversal attacks (../../) fail closed with AccessDenied.

Constant-Time Bearer Auth

In HTTP transport mode (--transport http), requests require a bearer token verified using crypto/subtle.ConstantTimeCompare to prevent timing side-channels.

Zero Cloud Telemetry

The MCP server runs 100% on your local machine over standard I/O or localhost sockets. Your code and graph topology are never sent to third-party telemetry collectors.
